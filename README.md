# 🛒 Commerce Web (쇼핑몰 결제 프로세스 시뮬레이션)

## 📖 프로젝트 개요
대용량 트래픽과 다중 사용자 요청 환경을 가정하여 안정적인 트랜잭션 처리와 동시성 제어에 집중한 이커머스 웹 서비스입니다.
두 명의 개발자가 프론트엔드와 백엔드를 모두 병행(Full-stack)하며, 결제 상태 변화에 따른 데이터 정합성 보장과 유기적인 협업 프로세스 구축을 목표로 진행했습니다.

## 👨‍💻 팀원 및 역할 (2인 프로젝트)
- **나영준 (풀스택)**
  - 백엔드 / 프론트엔드 공동 개발
  - **DevOps & 형상관리:** CI/CD 파이프라인 구축, Git 브랜치 전략(규칙) 수립, PR(Pull Request) 리뷰 및 병합 총괄
  - **Backend Core:** 결제 트랜잭션 처리 로직 구현, 동시성 이슈 제어, 쿼리 튜닝
- **문무찬 (풀스택)**
  - 백엔드 / 프론트엔드 공동 개발
  - **Frontend Core:** 장바구니 및 상품 조회 UI/UX 구현, API 연동
  - **Backend Core:** 상품 및 주문 도메인 비즈니스 로직 공동 설계

## 🛠 기술 스택 (Tech Stack)
- **Backend:** Java, Spring Boot, Spring Data JPA
- **Frontend:** React
- **Database:** MySQL
- **Infra & DevOps:** Docker, CI/CD, GitHub (PR & 형상관리)

## 💡 핵심 문제 해결 및 기술적 성과

### 1. 체계적인 형상관리 및 코드 리뷰 문화 정착 (리드 역할)
- **도입 배경:** 2인 풀스택 개발 특성상 프론트엔드와 백엔드 코드가 잦은 빈도로 충돌할 위험이 존재했습니다.
- **해결 및 성과:** 
  - 명확한 커밋 컨벤션과 Git Flow 기반의 브랜치 전략을 수립했습니다.
  - 모든 코드 변경 사항은 PR을 통해서만 병합되도록 규칙을 정하고, **리뷰어로서 직접 테스트 후 병합(Merge)을 승인**하여 코드베이스의 무결성을 지켰습니다.

### 2. 결제 상태 전이 모델링 및 단일 트랜잭션(@Transactional) 제어
- **도입 배경:** 결제 완료 시점에 재고, 주문, 이력 데이터 중 하나라도 누락되면 심각한 비즈니스 정합성 문제가 발생합니다.
- **해결 및 성과:** 
  - 실제 PG사 연동 없이 '주문 상태값 전이(결제 대기 → 완료/실패)' 흐름을 모델링하여 결제 과정을 시뮬레이션했습니다.
  - 재고 차감, 주문 확정, 이력 기록을 **단일 트랜잭션으로 묶어 원자성(Atomicity)을 보장**하고, 예외 발생 시 안전하게 롤백되도록 구현했습니다.

### 3. 동시성 이슈(Race Condition) 방어 로직 구현
- **도입 배경:** 한정된 상품에 다중 사용자의 주문 요청이 겹칠 때 발생하는 재고 차감 동시성 이슈를 예방해야 했습니다.
- **해결 및 성과:** 
  - 재시도 및 중복 요청을 고려한 방어 로직을 구성하여 동일 요청에 대한 결과의 일관성을 확보했습니다.
  - 데이터베이스 격리 수준(Isolation Level)을 적절히 설정하여 다중 사용자 환경에서의 Race Condition을 방지했습니다.

### 4. 핫스팟 엔드포인트 쿼리 튜닝
- **도입 배경:** 트래픽이 집중되는 상품 조회 및 주문 구간의 데이터베이스 병목 현상을 해결해야 했습니다.
- **해결 및 성과:** 
  - 실행 계획(Explain)을 분석하여 병목 구간의 쿼리를 튜닝하고 최적화된 인덱싱을 적용해 전반적인 API 응답 속도를 개선했습니다.
